# benjaminhattemer.com

Source of my personal academic website, built with [Hugo](https://gohugo.io/) and the [PaperMod](https://github.com/adityatelange/hugo-PaperMod) theme as adapted by [Pascal Michaillat's template](https://github.com/pmichaillat/hugo-website). GitHub Actions builds and deploys the site to GitHub Pages on every push to `main`.

## Layout

| Path | What it is |
|---|---|
| `config.yml` | Site settings, and the home page: profile text, photo, and the CV and Research buttons |
| `content/research/_index.md` | The Research page (publications, working papers, work in progress) |
| `content/teaching/_index.md` | The Teaching page (courses; course materials go here) |
| `content/cv.md` | The CV page: the CV written out on the website, with a link to the PDF |
| `content/location.md` | The Location page |
| `cv/CV.tex` | LaTeX source of the PDF CV |
| `assets/css/extended/cv.css` | Styling of the CV page (right-aligned dates, references grid) |
| `static/` | Files served as-is at the site root: `CV.pdf`, the profile photo, the favicon |
| `archetypes/` | Skeleton pages for papers, courses, and datasets (see below) |
| `layouts/`, `assets/` | Template customisations of the PaperMod theme; normally untouched |
| `themes/PaperMod` | The theme itself; never edited |
| `.github/workflows/hugo.yml` | The build-and-deploy workflow |

The `public/` folder is Hugo's build output. It is regenerated by GitHub on every push and is not committed.

## Everyday edits

**Home page text or photo.** Edit `params.profileMode` in `config.yml`. The photo is `static/picture_hat.jpg`.

**Research page.** Edit `content/research/_index.md`. Plain Markdown; HTML such as `<details>` for abstracts is allowed.

**CV.** Edit `cv/CV.tex`, then run from the repository root:

```powershell
.\cv\build.ps1
```

This compiles the PDF and copies it to `static/CV.pdf`, which the CV page links to. The CV button on the home page opens the CV page (`content/cv.md`), which writes the same CV out in Markdown and HTML. Any edit to `cv/CV.tex` is made in `content/cv.md` too, in the same commit. Phone numbers stay in the PDF only.

**Keep the Research page and the CV in line.** Both list the same publications and working papers. Work in progress appears on the Research page only, policy work on the CV only. Any change to one of them (a new project, a coauthor, a status such as *Submitted*, a new publication venue) is made in the other in the same commit. Section order and wording should match too; the CV can carry fewer details, but never a different list.

**Publish.** Commit and push to `main`. The site is live a minute or two later; progress is visible under the repository's Actions tab.

## Adding papers, courses, or datasets as their own pages

The template supports sections with one page per paper, course, or dataset. They were removed from this site because they only held placeholders, but they can be re-created in two steps.

1. Create the section index, for example `content/papers/_index.md`:

   ```yaml
   ---
   title: "Papers"
   description: "Preprints and articles on this website."
   ---
   ```

2. Add one page per item, using the matching skeleton in `archetypes/`:

   | Section | Skeleton | Page location |
   |---|---|---|
   | papers | `archetypes/paper.md` | `content/papers/<short-name>/index.md` |
   | courses | `archetypes/course.md` | `content/courses/<short-name>/index.md` |
   | data | `archetypes/data.md` | `content/data/<short-name>.md` |

   Copy the skeleton to the page location and fill it in. PDFs and images that belong to a paper or course go in the same folder as its `index.md` and are linked by bare filename, for example `[Paper](paper.pdf)`.

The template's own documentation at https://pascalmichaillat.org/d5/ describes the front-matter fields, and the archive and tags pages that list all items, which can be restored from the [template repository](https://github.com/pmichaillat/hugo-website/tree/main/content) if wanted.

## Local preview

Optional. Install [Hugo](https://gohugo.io/installation/), then run `hugo server` from the repository root and open http://localhost:1313. Changes to content show up live.
